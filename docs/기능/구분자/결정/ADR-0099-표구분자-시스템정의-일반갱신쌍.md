# ADR-0099 — 지급금액 표는 시스템 정의 표 구분자(일반 · 갱신 한 쌍)다 — 동적표 정의 객체를 대체한다

> 상태: 채택 (2026-11-01 사용자 결정) · 날짜: 2026-11-01 · **미구현** — 지금 코드는 동적표 정의 객체(`/dyntables` · `dynTableRef`, [[기능/동적표/동적표]])다.

## 맥락

동적표(2026-10-17 기획 · 2026-10-18 감액 표 구현 · 2026-10-31 정액형 구현)는 함수조항처럼 **사용자가 정의하는 독립 객체**다 — 코드 · 이름 · 인자 · 머리글 · 셀 · 캡션 템플릿을 정의에 적고, 담보약관 문면에 참조 노드 `dynTableRef` 를 넣어 인자를 연결한다.
그런데 정액형 표의 입력 창구(담보약관 편집기 모달)를 기획하다 보니, 표 하나가 나오는 데 필요한 것 대부분을 시스템이 정하고 있었다.

| 층 | 무엇 | 누가 정하나 |
|---|---|---|
| 입력 | 감액 · 지급률 · 가입금액 · 정액표 — 급부 · 담보 특성 폼 | 시스템(마스터 폼) |
| 펼침 | 행 · 열 · 셀 계산 · 블록 구성(`expand` · `expandFixed`) | 시스템(코드) |
| 인자 | 갱신형 · 단서문구 | 시스템 — 화면에서 못 고친다(2026-10-21) |
| 문구 | 머리글 · 셀 · 캡션 템플릿 | 사용자 |

표 종류가 하나 늘 때마다(체증형) 입력 폼과 펼침 코드를 시스템이 새로 만들어야 한다. 사용자 정의 객체가 실제로 쥔 것은 문구뿐이고, 그 문구도 표 종류마다 사실상 하나다.
또 감액은 상품 소유라([[기능/상품/결정/ADR-0097-필드소유-마스터소유-상품소유]]) 같은 담보약관이라도 상품담보마다 표가 다르다 — 「문맥마다 유효값이 정해진다」는 구분자의 성질 그대로다.

## 결정

1. **입력은 폼이다** — 감액(`reduction`) · 지급률(`pay`) · 가입금액(`insured_amount`) · 정액표(`fixed_table`). 담보 상세 · 상품담보 값 화면에서 적고, 소유 규칙은 ADR-0097 그대로다. 표만을 위한 입력 모달은 두지 않는다.
2. **표 구분자** — 결과 타입이 **표**인 구분자. 유효값 = 그 문맥(상품담보)의 폼 값으로 계산한 표다. 계산 종류(감액 지급금액 · 통합치료비 정액)와 문구는 **시스템이 정의하고 사용자는 고치지 않는다**. 구분자 메뉴에 읽기 전용으로 보이고 견본 미리보기를 준다.
3. **정의 하나 = 구분자 두 개(일반표 · 갱신표)** — 한 번 정의하면 코드가 둘 채번된다. 같은 입력에서 계산하지만 모양이 다르다 — 일반표는 감액 구간 열, 갱신표는 열 하나(지급률). 처음 둘 쌍:

   | 정의 | 일반표 | 갱신표 |
   |---|---|---|
   | 감액 지급금액 표 | 「보험금 지급금액표」 — 지금 `DT000001` | 「갱신 보험금 지급금액표」 — 지금 `DT000002` |
   | 통합치료비 표 | 「통합치료비 지급금액표」 — 지금 `DT000003` | 「갱신 통합치료비 지급금액표」 — 지금 `DT000004` |

4. **언제 어느 표를 내는지는 담보약관의 조건식이 정한다** — 표 구분자는 블록 자리에 놓는다.

   ```
   IF 감액 있음
     1. 이 특별약관에서 …
     {{ 보험금 지급금액표 }}
   END IF
   IF 감액 있음 그리고 갱신형
     2. 이 특별약관에서 …
     {{ 갱신 보험금 지급금액표 }}
   END IF
   ```

   「감액 있음」 = 그 상품담보에 감액이 모델링돼 있음 — 담보 레벨 구분자 `exist(reduction.periods)` 하나로 쓴다(기존 집계, [[기능/구분자/구분자]] §3.2).
5. **동적표 정의 객체 · `/dyntables` 메뉴 · `dynTableRef` 노드 · 인자 연결은 없앤다.** 펼침 계산(행 = 급부명 · 열 = 감액 구간 · 셀 = 지급률 × 감액, 정액형 블록) · 금액 표기 · 출처 패널 기록은 표 구분자의 계산으로 옮긴다.

## 이유

- 표 종류는 어차피 시스템이 만든다 — 사용자 정의 객체를 두면 「정의는 사용자 것인데 종류 · 인자 · 입력은 시스템 것」이라 객체의 주인이 둘이 된다.
- 구분자는 이미 「문맥마다 유효값이 정해지는 이름 붙은 값」이다. 상품담보마다 감액이 달라 표가 달라지는 것이 정확히 그 성질이고, 담보약관 작성자는 다른 구분자와 똑같이 조건식과 자리로 쓴다 — 새 개념(동적표 · 인자 연결 · 표 고르기 팝업)을 배울 일이 없다.
- 일반 / 갱신을 쌍으로 채번하면 표 안의 「항상 생성 · 갱신형만 노출」 같은 숨은 규칙 없이 문면 조건식이 다 보인다(동적표의 「(갱신) 표 = 두 번째 정의 + 조건 노드」 결정과 같은 결).

## 버린 대안

- **동적표 정의 유지 + 정의를 「표 종류의 문구 변형」으로 낮추기** — 코드를 가장 적게 바꾸지만 사용자 정의 객체 · 인자 연결 · 표 고르기가 그대로 남는다. 문구를 사용자가 고칠 실익이 없다.
- **표를 특성(폼)에 딸리게 하고 문면 노드 옵션으로 문구 고르기** — 문면 노드가 폼을 직접 가리키게 돼 「조문은 구분자만 본다」([[기능/구분자/결정/ADR-0036-폼-구분자-문면-3층]])를 깬다.
- **문구를 담보 특성 필드로(담보마다 저장)** — 같은 문구를 담보마다 반복해 적는다.
- **표 하나 = 구분자 하나(갱신 모양은 표 안에서 갈림)** — 문면에서 일반 · 갱신 표를 따로 놓을 수 없고, 갈림이 표 안에 숨는다.
- **「감액 있음」 구분자를 정의할 때 자동 채번(셋째 구분자)** — 기존 집계 `exist` 로 담보 레벨 구분자 하나면 된다.

## 결과와 감수하는 비용

- 구분자에 **시스템 정의 · 수정 불가** 종류가 생긴다 — 「식은 데이터다 · 편집자가 배포 없이 만든다」([[기능/구분자/구분자]] §3.1)의 예외다. 새 표 종류(체증형 · 월간한도 계열 캡션)는 시스템 배포로 늘린다.
- 결과 타입에 **표**가 더해진다 — 식에서 읽을 수 없고(조건 · 집계 · 다른 구분자의 식 모두 거부), 문면의 블록 자리에만 놓는다. 보통약관 문맥이면 오류다.
- 담보마다 다른 머리글 꼬리(주요치료비 단서문구)는 인자가 없어지므로 **담보 특성(마스터 소유)** 으로 옮겨 표 구분자가 스스로 읽는다. 기준일 낱말(「최초계약일」 / 「계약일」)은 시스템 문구 안 조건이 그 상품담보의 갱신형 값을 읽어 고른다.
- 이미 만든 동적표 코드(정의 화면 · 저장 검사 · 문서 편집기 팝업 · 인자 연결 · 관계정보 간선 · `dyn_tables` 테이블)를 걷어낸다. 시드 문면에서 `dynTableRef` 를 쓰는 곳은 없다(2026-11-01 확인).
- 담보약관 편집기의 동적표 입력 모달(정액표 · 가입금액을 문면에서 고치고 문서와 함께 저장하는 안 — 2026-10-31 방향 · 2026-11-01 세부)은 폐기한다 — 입력은 폼 화면이 맡는다.
