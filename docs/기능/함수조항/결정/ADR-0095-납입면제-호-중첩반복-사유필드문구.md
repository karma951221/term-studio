## 맥락 — 바꾸기 전 구조 (2026-10-29 시드)

```
IF 납입면제 있음
제29조(보험료의 납입면제)                       ← 통합간편. 알파Plus 는 제27조의1
  [⟳ 납입면제종마다]  (원천: waiver 선택지 · 적용여부 = 예)
    ① 회사는 〔현재 종 번호〕종(〔현재 종 이름〕)… 다음 중 어느 하나의 사유에 해당되고 …
       ⟨C0022 호 — 암·면책 (종들 ← 현재 종)⟩      본문: IF var.해당 → 1. …
       ⟨C0023 호 — 암·무면책 (종들 ← 현재 종)⟩
       … C0033 까지 12 개 고정 나열
  ② ⟨면제 부가항⟩ …
```

- **종 여럿은 이미 된다.** 바깥 반복이 종마다 항을 하나씩 펴므로 통합간편 ① ② 가 이 템플릿 하나에서 나온다(`waiver.test.ts` 「제29조 ① ② = [납입면제종마다] 항 하나」). 각 호 함수조항의 `IF var.해당` 은 **현재 종**의 사유만 보므로 항마다 그 종의 사유 호만 남는다.
  편집 화면에 ① 하나만 보이는 것은 템플릿이 반복 본문 한 벌이기 때문이다 — 「종이 하나인 경우만 다루고 제1항에만 조건이 걸린」 구조는 아니다.
- **실제 문제는 하나** — 호 자리가 사유 수만큼 고정 나열이라 길고, 사유를 더하면 함수조항 하나 + 템플릿 두(세) 벌에 참조 하나씩을 더해야 한다.
- 호 문구 12 개 가운데 10 개는 한 틀이다: 「피보험자가 [면책이면 「암보장개시일 이후」]「〈약관표시명〉」(으)로 진단확정되었을 경우」.
  다른 것은 V11 상해및질병80%이상후유장해(호 둘 · 별표 참조) 하나, V14 는 원문 띄어쓰기(「피보험자가 「」) 한 칸 차이.

## 결정 (안)

1. **호 자리는 중첩 반복 + 호 함수조항 하나다.**
   ```
   [⟳ 납입면제종마다]
     ① 회사는 〔현재 종〕… 다음 중 어느 하나의 사유에 해당되고 …
        [⟳ 현재 종의 사유마다]                         ← 안쪽 반복, 열거형 순서
          ⟨납입면제 호 (사유 ← 현재 사유)⟩
   ```
   사유를 더해도 조 모양은 그대로다. 종이 몇 개든 같다.
2. **호 함수조항 「납입면제 호」 — 인자 「사유」(enum E0001), 본문은 사유 필드로 문구를 짓는다(값 코드 비교 없음).**
   ```
   IF arg.사유.장해호                                 ← 새 참거짓 필드 F04 「장해호」(V11 = 예)
     P0100 피보험자가 상해로 [별표] 에서 정한 장해지급률이 80% 이상 …
     P0200 피보험자가 진단 확정된 질병으로 [별표] 에서 정한 …
   그 밖의 경우
     P0100 피보험자가 [IF arg.사유.F02(면책여부) → 암보장개시일 이후]「〔arg.사유.F01 약관표시명〕」{(으)로} 진단확정되었을 경우
   ```
   - P코드는 가지 짝이 같은 자리를 나눈다(상해 호 · 진단 호 = P0100, ADR-0077 결정 6).
   - 진단형 사유를 더할 때는 **열거값 하나만 더한다**(약관표시명 · 면책여부) — 함수조항 · 템플릿을 고치지 않는다.
   - 진단형이 아닌 새 모양이 생기면 그때 필드(모양)를 늘리고 가지를 더한다.
3. **특정 사유의 호를 가리키는 참조는 값 한정으로 쓴다** — 세부규정 · 부가항의 「제1항 제1호」 = `{ 호 함수조항 참조, restrict: { values: [V01] } }`, 통합간편 「상해 호」 = `{ …, innerCode: P0100, restrict: { values: [V11] } }`, 같은 대상에 모인 사유는 한정 하나로 모은다(「제4호 … 제6호」 = `values: [V11, V14]`).
   종이 둘이면 종마다 생긴 번호가 모두 찍힌다(지금과 같은 결과).
4. **조 참조 패널의 값 한정 칸은 손대지 않는다** — 칸은 문서에 열거값 반복이 있을 때만 그려진다(`Popups.tsx restrictAt` — 반복 원소 열거형의 값이 후보). 보통약관 템플릿에 [현재 종의 사유마다]가 생겨 칸이 데이터로 다시 나온다. 한정 없이 그 호를 가리키면 모든 사유의 호다.
5. **정의 조 · 부가항 · 세부규정 · 무효 · 부활 · 「납입면제 있음」은 그대로** — 정의는 상품군마다 문장째 달라 사유별 함수조항이 맞다(ADR-0086 결정 3). 이들은 호 노드를 가리키지 않거나(조 · 반복 항 참조) 결정 3 으로 옮긴다.

## 이유

- 조 길이가 사유 수와 무관해진다. 사유 추가가 열거값 한 줄이 된다 — 지금은 함수조항 + 템플릿 참조 + (가리키면) 조 참조.
- 사유 문구의 진실이 **열거값(약관표시명 · 면책여부)** 한 곳이다 — 정의 조 · 상품 화면이 이미 같은 필드를 읽는다.
- ADR-0077 결정 1(템플릿은 값으로 분기하지 않는다)을 지키고, 함수조항 안에서도 값 코드 비교가 없다(필드로 가른다).
- 엔진 변경이 없다 — ADR-0086 이전 모양이 이미 돌던 기계다.

## 버린 대안

| 안 | 버린 이유 |
|---|---|
| 지금대로 사유별 함수조항 12 + 편집기에서 접기만 | 조가 짧아 보일 뿐 사유 추가 비용(함수조항 · 템플릿 · 참조)은 그대로 |
| 중첩 반복 + 호 함수조항 하나 안 **값별 분기(switch) 12 칸** | ADR-0086 이전 모양. 길이가 함수조항 안으로 옮겨 갈 뿐이고, 사유를 더하면 칸을 더해야 한다. 10 칸이 같은 글이라 중복 |
| 중첩 반복 + **열거값 필드 「호 함수조항」으로 함수조항을 골라 펼침** | 사유별 블록(ADR-0086 의 장점)은 남지만 「동적 함수조항 참조」라는 새 장치(데이터 모델 · 조립 · 저장 검사 · 편집기)가 든다. ADR-0086 이 「대응표」로 이미 버렸다 |
| 호 함수조항 안에서 `arg.사유 = 'V11'` 로 장해 가르기 | 값 코드가 함수조항에 박힌다. 필드 하나(장해호)면 같은 일을 값 코드 없이 한다 |

## 결과와 감수하는 비용

- **ADR-0086 결정 1 의 「작성자가 보는 단위는 사유 블록」을 호에서는 놓는다** — 사유 하나의 호 문구를 고치려면 함수조항이 아니라 열거값 필드를 고친다. 진단형이 아닌 문구를 사유 하나만 바꾸고 싶으면 필드 · 가지가 는다.
- 원문 차이 하나 — 「중대한재생불량성빈혈」의 조사. 조사 칩은 약관표시명 끝 글자로 고른다(혈 — ㄹ 받침 → 「로」), 원문은 「으로」. 알려진 차이(2604 · 2607 보통약관)로 올렸다 — 실물 재현 허용 차이(함수조항 공통화 우선).
- 호 함수조항 11 개가 지워져 뒤 코드가 11 씩 당겨졌다(ADR-0086 결정 8 과 같은 비용) — 코드를 쓰는 테스트 · 실물 명세 · 기능 문서를 함께 고쳤다. 바탕 시드는 함수조항 C0001 ~ C0042, 화면 E2E 는 C0043 부터.
- 값 한정이 다시 쓰인다 — 세부규정 · 부가항의 호 참조가 `restrict: { values }` 를 싣는다.
- 보통약관 통합(「보통약관(일반)」, `general-terms-template-merge`) 위에서 구현했다 — 그 브랜치가 main 에 먼저 들어가야 한다.
