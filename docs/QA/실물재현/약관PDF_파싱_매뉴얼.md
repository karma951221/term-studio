# 약관 PDF 파싱 매뉴얼

> 상태: 초안 · 최종수정: 2026-11-03

약관 PDF 한 권을 **terms-studio 시드(보통약관 템플릿 · 담보약관 템플릿 · 담보 · 상품)** 로 넣기까지의 절차다.
이 문서만 보고 새 상품을 넣을 수 있게 쓴다 — 실제 파싱 · 조립은 클라우드 세션이 [[약관PDF/2610/목록]]의 PDF 로 한다(2026-11-03 사용자 결정).
앞선 실물 재현 경위는 [[QA/시나리오/실물재현_E2E_시나리오]] · [[QA/실물재현/알파플러스2607_원문구조]] · [[QA/실물재현/알파플러스2607_모델명세]].

기준은 **완벽 재현이 아니라 함수조항 공통화가 먼저**다 — 항 순서 · 별표 번호 · 일부 문구 차이는 허용하고, 허용한 차이는 [[QA/인수기준]] 「알려진 차이」(`src/db/seed/knownDifferences.ts`)에 적는다.

## 1. 한눈에

```
PDF (docs/약관PDF/2610/*.pdf)
 │ ① 추출 — scripts/terms/pdf/build_terms_md.py (PyMuPDF)
 ▼
추출 md (docs/_자료/<상품>/00_주계약/*.md · NN_<독립특약>.md · _structure.json)   ← gitignore, 언제든 다시 뽑는다
 │ ② 양식 변환 — npm run terms:pdfmd (scripts/terms/pdfmd/)
 ▼
파싱양식 fixture (tests/fixtures/terms/<상품>/*.md)                                   ← 커밋한다
 │ ③ 등록 — scripts/terms/config.ts (ProductTerms · 특약 한 줄씩) + products.json 상품
 │ ④ 변환 — npm run terms:convert
 ▼
시드 JSON (src/db/seed/data/{generals,documents,appendices,boxes,clauses,coverages,products}.json)
 │ ⑤ 확인 — npm test (real.test.ts 원문 대조) · rm -rf .data && npm run db:seed · 화면
```

|---|---|---|
| ① 추출 | 목차 쪽 · 쪽 오프셋 · 상품명 조각(목록에 있다) | 2단 조판 읽기 · 쪽번호 · 음영 띠 제거 · 표 · 상자 · 관 · 조 · 특약 머리 · 목차 대조 |
| ② 양식 변환 | 어느 특약을 넣을지(`--only` · `--all`) | 항 · 호 · 목 마커 · 쪽 경계 문장 잇기 · 박스 · 그림 자리 · 번호 어긋남 표시 · `parseTerms` 재검사 |
| ③ 등록 | 상품 · 담보분류 · 갱신형 짝 · 별표 번호 대응 | — |
| ④ 변환 | — | 조 · 별표 참조 슬롯 · 함수조항 공통화 · 박스 · 감액 지급금액 표 → 표 구분자 · 갱신형 짝 합치기 |

## 2. 파일 · 폴더 규칙

- 인코딩 UTF-8 · 개행 LF.
- 날짜는 절대 날짜. 추출 md 의 추출일은 실행일이 찍힌다.

## 3. ① 추출 — PDF → 추출 md

### 3.1 준비

- PyMuPDF(`fitz`)는 **macOS 시스템 python 의 사용자 site-packages** 에 있다 — `python3 -I` 로는 못 읽는다. 클라우드 등 새 환경이면 `pip install --user "pymupdf==1.26.5"` 먼저.
- **PyMuPDF 는 1.26 판으로 고정한다** (2026-11-03). 2.x(MuPDF 1.28)는 표 인식(`find_tables`)이 달라 감액 표 · 지급금액 표의 행이 빠지거나 두 단이 한 표로 엉킨다(알파Plus2610 2대질환 통합생활지원비 · 131대질병수술비 — 2607 fixture 와 대조해 찾았다). 다른 판이 이미 깔린 환경이면 `pip install --target <폴더> "pymupdf==1.26.5"` 뒤 `PYTHONPATH=<폴더>` 로 돌린다.
- 리포 **밖**의 cwd 에서 실행한다(스크립트 경로 · PDF 경로를 절대 경로로 넘긴다).
- 큰 PDF(1800쪽)는 4 ~ 5분 걸린다.

### 3.2 인자 맞추기

`목록.md` 의 값을 그대로 쓰되, 먼저 `--parts` 로 목차 대분류가 맞게 읽히는지 본다.

```bash
python3 scripts/terms/pdf/build_terms_md.py "<PDF>" /tmp/x --toc 27-34 --offset 1 --product "뇌심보험" --parts
```

출력은 「목차 쪽 · 대분류 제목」 줄이다. 맞으면 다음이 보인다.

```
27 무배당 올케어 꽉 채운 뇌심보험(세만기형) 2610(일반심사형) 보통약관
29 무배당 올케어 꽉 채운 뇌심보험(세만기형) 2610(일반심사형) 특별약관
31 기타 제도성 특별약관
32 무배당 갱신형 간편한 산정특례 진단비보장 특별약관2610(일반심사형)
```

| 인자 | 뜻 | 정하는 법 |
|---|---|---|
| `--toc A-B` | 인쇄 목차가 있는 PDF 쪽(1-base, 양끝 포함) | 점선 지시자(`…… 123`)가 있는 첫 연속 쪽 |
| `--offset N` | PDF 쪽 − 인쇄 쪽 | 본문 쪽 아래 쪽번호와 PDF 쪽의 차. 2610 판은 모두 1 |
| `--product S` | 주계약 보통약관 · 특별약관 목차 제목에 **둘 다** 든 글 | 보통약관 대분류 제목에서 「보통약관」을 뗀 것. 목록의 값 |

대분류가 `--product` 와 안 맞으면 그 대분류는 **독립특약**으로 읽혀 `제N절` · `가입자 유의사항` 목차 줄을 찾다 멈춘다(`StopIteration`). 그때는 `--product` 를 줄인다.

### 3.3 실행 · 대조

```bash
python3 scripts/terms/pdf/build_terms_md.py "<PDF>" "docs/_자료/<상품 폴더>" --toc A-B --offset N --product "S"
```

```bash
python3 scripts/terms/pdf/verify_structure.py "docs/_자료/<상품 폴더>/_structure.json"
```

`verify_structure` 는 목차 행(관 · 조 · 특약 · 별표)과 추출한 제목을 대조한다 — 단위마다 `누락 0 / 초과 0`, 끝줄 `TOTAL 누락 0` 이 목표.
누락 · 초과가 남으면 그 쪽을 PDF 로 열어 보고 §7 에 적는다(대부분 제목이 두 줄로 찍혀 하나로 붙은 경우다).

### 3.4 산출 구조

| 파일 | 무엇 |
|---|---|
| `00_주계약/01_보통약관.md` | 주계약 보통약관(특별약관 대분류가 없는 상품은 특별약관까지 — §7.2) |
| `00_주계약/0N_특별약관_<로마숫자>_<대분류>.md` | 주계약 특별약관 대분류(상해 관련 · 질병 관련 · 상해 및 질병 관련 · 비용손해 관련 · 기타)마다 하나 — 특약 수십 ~ 백여 개가 한 파일 |
| `00_주계약/0N_별표.md` | 주계약 별표 전부 |
| `00_주계약/09_기타제도성특별약관.md` | 기타 제도성 특별약관 + 그 별표 |
| `NN_<독립특약 이름>.md` | 독립특약 하나씩(표지 · 가입자 유의사항은 뺀 본문) |
| `_structure.json` | `units`(단위별 쪽) · `toc`(목차 행 — `printed` 인쇄 쪽 · `pdf` PDF 쪽) · `headings`(추출한 제목 전부) |

**빼는 범위**: 표지 · 안내문 · 가이드북 · 약관요약서 · 목차 · 가입자 유의사항 · 주요내용 요약서 · 보험용어 해설 · 인용 법 규정(【법규N】) · 가나다순 색인.

### 3.5 추출 md 표기 (② 의 입력)

| 표기 | 무엇 |
|---|---|
| `# <상품> 보통약관` · `> 원본: <PDF> · PDF p.A–B · 추출 YYYY-MM-DD · …` | 파일 머리 — 원본 줄은 지우지 않는다(`readSourceMeta`) |
| `## 제N관 제목` · `### 제N조(제목)` | 관 · 조 (절형 보통약관은 한 단계씩 깊다 — §7.1) |
| `## N. 이름 특별약관` | 특약 하나의 시작 |
| `[N] 본문` · `① 본문` · `1) 본문` | 항 · 호 · 목 |
| `> 【제목】 본문` · `> 본문` | 네 변 선 상자(용어 설명 · 법령 인용) |
| `| a | b |` | 표 |
| `【제목】` · `[제목]` 한 줄 | 예시 · 그림 묶음의 제목 |
| `[그림 — 원문 PDF p.N]` | 옮길 수 없는 도식 자리 |
| `**…**` | 굵은 소제목(통합형 특약 「**3.(보장의 소멸)**」 · 절형 보장 이름) |
| `<!-- p.N -->` | 쪽 경계 |

### 3.6 잡음 제거 — 추출기가 하는 것 · 사람이 볼 것

추출기가 한다(`pdf_layout.py`): 2단 조판을 좌단 전체 → 우단 전체로 읽기 · 하단 쪽번호(Helvetica-Bold 숫자) 버리기 · 회색 음영 패널(글줄마다 칠한 띠)을 표가 아니라 본문으로 · 안쪽 가로줄 없는 표를 짧은 값 열의 줄 위치로 행 재분할 · 글꼴 매핑 잡음(`ž` → `･`, 간병인지원 특약명의 보이지 않는 `Q`) 지우기.

사람이 볼 것:

- 단 경계 · 쪽 경계에서 문장이 이어지는지(②가 `<!-- p.N -->` 앞뒤를 잇지만, 머리말 · 꼬리말 글자가 끼면 안 잇는다).
- 머리말(상품명 · 쪽 제목)이 본문 줄로 남았는지 — 남으면 `pdf_layout.py` 에서 그 글꼴 · 위치를 거른다(판마다 다를 수 있다).
- 표가 상자로, 상자가 표로 바뀌지 않았는지 — 같은 쪽 PDF 와 비교.

## 4. ② 양식 변환 — 추출 md → 파싱양식 fixture

```bash
npm run terms:pdfmd -- "docs/_자료/<상품 폴더>/00_주계약/02_특별약관_Ⅰ_상해관련.md" --list
```

```bash
npm run terms:pdfmd -- "docs/_자료/<상품 폴더>/00_주계약/02_특별약관_Ⅰ_상해관련.md" --out "tests/fixtures/terms/<상품>" --all
```

- `--list` 는 특약 목록(`#번호 · 쪽 · fixture 이름 · 원문 제목`). `--only "이름1,이름2"` · `--only-file 목록.txt` · `--all` 로 고른다(이름은 원문 이름 · 「특별약관」 뗀 이름 · fixture 이름 · `#N`).
- 만든 파일은 모두 `parseTerms` 로 다시 읽는다 — 양식을 어기면 쓰지 않고 멈춘다. `[경고] 옮기지 않은 머리줄` 이 나오면 그 머리가 양식 밖이라는 뜻이다(§7).
- 상품을 다 넣을 때는 `presets.ts` 에 preset 을 만들고 `npm run terms:pdfmd -- --preset <이름>` 으로 다시 만든다(재생성이 한 명령).

### 4.1 파싱양식 (fixture 문법 — `scripts/terms/parse.ts`)

```
# <문서 제목>
> 출처: <PDF> PDF N쪽(인쇄 M쪽) · 추출일: YYYY-MM-DD
> 상품: <상품명> · 문서종류: 보통약관 | 특별약관
```

| 줄 머리 | 계층 | 원문 마커 |
|---|---|---|
| `# 제N관 제목` | 관 | 「제1관 목적 및 용어의 정의」 |
| `## 제N조(제목)` · `## 제N조의M(제목)` | 조 — 가지번호 `의M` 을 생략하지 않는다 | |
| `= 본문` | 항 번호 없는 조의 단독 본문 — 조에 항이 하나도 없을 때만 | |
| `@ 본문` | 항 — 한 항 = 한 줄 | 사각 숫자 `[1]` |
| `  - 본문` (공백 2) | 호 | ① ② ③ |
| `    - 본문` (공백 4) | 목 | 1) 2) 3) · 가. 나. |
| ```` ```표 ```` … ```` ``` ```` | 정적 표 — 첫 줄 `제목: …`(없으면 `(없음)`), 다음 마크다운 표. 병합 셀은 값을 반복하고 `<!-- 병합 -->` | |
| ```` ```용어풀이 ```` | 박스 — 첫 줄 `【제목】`(없으면 제목 없는 박스), 나머지 줄 그대로 | |
| ```` ```그림 ```` | 옮길 수 없는 도식 — `설명: …` 한 줄 | |
| `> 통계: 관 N · 조 N · 항 N · 호 N · 목 N · 표 N` | 파일 끝 통계 | |

- **마커 글자(①, `[1]`, `1)`)는 본문에 남기지 않는다** — 순서가 곧 번호다. 원문 번호가 순서와 어긋나면(결번 · 중복) 줄 끝에 `<!-- 원문번호: N -->`.
- 본문의 조 참조(`제N조(제목)` · `제N조 제M항 제K호`)와 별표 참조(`【별표N(이름)】`)는 **원문 그대로** 둔다 — ④ 변환기가 참조 슬롯으로 바꾼다.
- 마커 밖의 줄은 오류다(`parseTerms` 가 멈춘다).
- 항 번호 없는 머리말 뒤에 항이 오면 머리말을 첫 항에 붙인다 — 항 번호가 밀리면 「제N항」 참조가 틀어진다.
- 문장이 끝난 뒤 마커 없이 오는 줄(※ 주석)은 제목 없는 박스로 남긴다 — 본문에 섞지도, 버리지도 않는다.

## 5. 별표 · 표

| 무엇 | 처리 |
|---|---|
| 별표(분류표 · 장해분류표 · 수술분류표 …) | 담보약관 템플릿에는 넣지 않는다 — 별표는 공용 마스터([[기능/별표/별표]]), 조문은 참조만 한다. ④ 변환기가 `【별표N(이름)】` 을 별표 참조로 바꾸고, 처음 참조한 별표를 `appendices.json` 에 더한다(이름은 본문 참조 표기). 원문 번호 → 별표 코드 대응은 상품 설정 `appendixNumbers` — 이름이 같은 별표는 기존 코드(`APPENDICES`)에 잇는다(메리츠 예: 원문 14 장해분류표 → `AX000002`). 별표 시드는 코드 · 이름뿐이라 `0N_별표.md` 의 별표 본문은 옮기지 않는다 |

## 6. ③ ④ 조립 — fixture → 시드

### 6.1 상품 설정 (`scripts/terms/config.ts`)

`ProductTerms` 하나를 만들고 `PRODUCTS` 에 더한다.

| 필드 | 무엇 |
|---|---|
| `code` · `seedCode` | 변환 코드 · `products.json` 의 상품 code |
| `line` | 상품군 — 납입면제 · 준용규정 함수조항이 상품군 것이다(ADR-0086 결정 7). 지금 `"alpha"` · `"meritz"` 둘뿐 — 새 상품군이면 넓혀야 한다(§7.4) |
| `fixtureDir` | `tests/fixtures/terms/<상품>` |
| `appendixNumbers` | 원문 별표 번호 → 별표 코드 |
| `general` | 보통약관 설정 — 같은 상품군 판이면 앞 판 것을 펴고(`...ALPHA2607_GENERAL`) `code` · 형 축 문장(`formAxisConds`)만 고친다 |
| `specials` | 담보약관 — **자동 탑재 한 줄**이 기본: `autoSpecial(글자, 담보분류, 사용자 그룹?)(목록 번호, fixture, 갱신형 fixture?)` |

자동 탑재(`auto.ts`)는 fixture 한 줄로 담보 · 템플릿 · 탑재를 만든다 — 담보명 · 갱신유형은 원문 제목, 보험금명은 「특별약관의 소멸」 첫 항, 특약 그룹은 담보분류(상해 V01 · 질병 V02 · 비용손해 V03) + 상품 사용자 그룹(「상해 및 질병 관련 특별약관」 · 「기타 특별약관」 — [[기능/상품/결정/ADR-0090-특약그룹-담보분류기본그룹-상품사용자그룹]]).
같은 담보의 비갱신 · 갱신형 원문은 **짝**으로 한 줄(`renewal` 자리)에 둔다 — 담보 하나 · 템플릿 하나 · 탑재 둘. 갱신형만 있는 특약은 갱신형 fixture 를 `file` 에.
손으로 설정하는 특약(슬롯 · 함수조항 쓰임을 지정)은 [[QA/시나리오/실물재현_E2E_시나리오]] §6.

보통약관은 **템플릿 하나**다 — 「보통약관(일반)」(`GENERAL_TEMPLATE` · `merge.ts`). 새 판은 판마다 고른 조만 상품 조 사본(`copies`)으로 제 글을 지키고, 상품군 · 기본계약마다 모양이 다른 조는 변형(`variants`)이다. 어느 조를 사본으로 둘지는 변환기가 알린다(`refMismatches`).

## 7. 2610 판에서 막히는 곳 (2026-11-03 시험 추출)

상해안심보험2610 · 뇌심보험(세만기형)2610(일반심사형)을 ① · ② 로 돌려 본 결과다. ①은 둘 다 돌았고, ② 에서 아래가 걸린다. **조립 전에 풀어야 한다.**

### 7.1 절형 보통약관 — 「제1절 일반조항 + 제2절 보장조항」 (2026-11-04 해결)

해결: `pdfmd` 가 제1절 = 보통약관, 제2절 보장마다 문서종류 「보장조항」 fixture 로 나누고(`splitUnits`), `refs.ts` 는 「보통약관 제1절 일반조항 」 · 「제1절 일반조항 」 접두를 보통약관 조 참조로 읽는다 — 절 이름은 조립의 위치 호칭이 다시 찍는다.
보장조항 문서는 기본계약 자동 탑재(`auto.base` — 섹션 base)이고 조연결이 없어 절 형태다(ADR-0100 — 보장 하나여도). 제1절의 제3 · 4조(「제2절 보장조항에서 정합니다」)는 조 사본.
아래는 처음 막혔을 때의 기록이다.


2610 판 보통약관은 2607 의 「관 > 조」가 아니라 `## 제1절 일반조항`(그 아래 `### 제N관` · `#### 제N조`) + `## 제2절 보장조항`(기본계약 보장마다 `**2-1. 이름**` 또는 `**이름 보장**` 굵은 줄, 그 아래 `### 제1조` 부터 다시)이다. 특약의 준용규정도 「보통약관 제1절 일반조항을 따릅니다」로 바뀌었다.
지금 `pdfmd` 는 절 머리를 「옮기지 않은 머리줄」로 경고하고, 보장조항을 보통약관 한 문서에 이어 붙여 **제1조가 여러 번** 나온다(상해안심 보통약관 조 57).
풀 일: `pdfmd` 가 제1절을 보통약관 한 벌로, 제2절의 보장 하나하나를 기본계약 담보약관 fixture 로 나눈다(관 · 조 머리 깊이 한 단계 올리기 포함). 준용규정의 「제1절 일반조항」 참조를 보통약관 참조로 풀지(`refs.ts`)도 정한다.

### 7.2 특별약관 대분류가 없는 상품 (2026-11-03 pdfmd 해결 — `### N.` 을 특약으로, 뇌심2610 2026-11-04 적용)

뇌심보험처럼 주계약 특별약관에 「Ⅰ. 상해 관련 …」 대분류가 없고 바로 「Ⅰ. 별표」가 오면, 특약이 `01_보통약관.md` 안에 `### N. 이름 특별약관`(한 단계 깊게)으로 붙는다. `pdfmd` 는 `## N.` 만 특약으로 나누므로 경고를 낸다.
풀 일: 추출기에서 보통약관 다음 특약 머리를 새 파일(`02_특별약관.md`)로 나누거나, `pdfmd` 가 `### N.` 도 특약 머리로 받게 한다.

### 7.3 목차 대조 누락

상해안심의 독립특약 「갱신형 가족일상생활중배상책임보장」은 목차의 「제2절 보장조항 2-1. …」이 한 줄로 붙어 `verify_structure` 누락 4 가 남는다(본문 추출은 됐다). 독립특약은 담보 모델 밖이면 넘어간다.

### 7.4 새 상품군 — 두지 않는다 (2026-11-04 결정 메모)

`ProductTerms.line` 은 `alpha` · `meritz` 둘이고 **더하지 않는다**. 상품군 꼬리표가 고르는 것은 납입면제 세 조 · 준용규정 함수조항 무리(ADR-0086 결정 7)뿐이다.

| 결정 | 왜 | 버린 안 |
|---|---|---|
| 알파Plus2610 = `alpha`, 상해안심2610 = `meritz` | 상해안심은 납입면제가 없고 보통약관이 자동갱신형(계약의 자동갱신 · 갱신계약 해제)이라 통합간편 무리와 같다 — 상품군 함수조항을 새로 쓸 일이 없다. 특약 준용규정은 자동 탑재가 원문 글대로 함수조항을 찾는다 | 상품마다 새 상품군(상해안심 · 뇌심) — 납입면제 없는 상품은 상품군 함수조항이 비어 꼬리표만 늘어난다 |

이름이 같은 다른 상품군 담보(상해안심의 갱신형 상해수술비 · 골절진단비Ⅱ 등 17)는 **알파 담보를 그대로 탑재**한다(2026-11-04 사용자 결정 — 담보명은 전역 유일). 원문 글은 다르다 — 파일 판 대조(알파 글) 위에 그 상품 문맥의 글 바꾸기(위치 호칭 · 납입면제 없는 준용예외)를 얹는다(`knownDifferences.ts` 「상해안심2610」).
알파 담보의 준용규정이 알파 납입면제 세 조를 가리키므로 그 상품은 세 조를 노출해 둔다(`GeneralSpec.keepShown` — 납입면제 미적용형이라 조립이 뺀다).

### 7.5 담보 모델 밖

실손 · 저축 · 연금 · 펫 · 재물 상품은 정액 급부 담보 모델 밖이다(`목록.md` 비고) — 넣지 않는다. 연금 · 저축은 목차 대분류 모양도 달라(「보통약관(적립형)」 · 대분류에 「보통약관」 없음) 추출 인자부터 맞지 않는다.

### 7.6 특약 머리의 가입 조건 줄

알파Plus2610 특약 78개는 머리에 「＊ 이 특별약관은 1형(해약환급금 지급형) 가입시에 한하여 가입가능합니다」(2종 하나) 줄이 있다. 약관 본문이 아니라 가입 조건 안내라 `pdfmd` 가 「조 밖의 줄을 버림」 경고와 함께 버린다 — 그대로 둔다(경고 78 은 이 줄이다). 상품담보 세목 부착으로 옮길 일은 조립 밖이다.

### 7.7 같은 상품군의 새 판 — 공유 · 교체 (2026-11-03)

알파Plus2610 은 2607 과 같은 상품군이다. 특약 fixture 를 2607 것과 본문 대조해(공백 · 그림 쪽 번호 무시 — `tests/fixtures/terms/알파2610/_2607대조.json`)

- **개정됐으면** 2607 담보 템플릿을 새 판 원문으로 바꾼다 — `SpecialSpec.fixtureDir`(설정 `REVISED_IN_2610`). 담보명은 전역 유일이라 같은 이름 새 담보를 둘 수 없다(사용자 결정). 앞 판 상품은 그 특약이 새 판 글로 찍혀 파일 판 대조(알려진 차이)가 된다. 2604 상품도 쓰는 담보는 바꾸지 않는다.
- **처음 실은 것**은 새 접두(`a10-*`)의 자동 탑재다.
감액 지급금액 표 차이는 조립 결과와 원문을 대조해 `paymentTableAt` 항목으로 뽑는다(표 구분자 모양 — §5).

`GEN_PRODUCT=… GEN_DIR=… GEN_CODE=… GEN_OUT=… npx vitest run src/db/seed/genDifferences.test.ts` 로 모아 `generatedArticle` 항목으로 적는다.
다른 상품 담보를 그대로 실을 때, 그 담보가 가리키는 보통약관 조는 사본으로 바꾸면 깨질 수 있다 — 템플릿 글로 두고(`GENERAL_TEMPLATE.templateKept`) 알려진 차이로 적는다.
