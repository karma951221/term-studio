# ADR-0094 — 목록 → 상세는 한 화면 — 항목 탭 · 왼쪽 목록 패널 · 편집은 한 탭만

> 상태: 채택 · 날짜: 2026-10-28
>
> 화면 규칙은 [[공통/화면/디자인원칙]] §2 「목록 → 상세」 · §1.7 · §1.9. 이 ADR 은 뼈대와 버린 안을 남긴다.

## 맥락

목록(L1)에서 항목을 누르면 상세(L2 · L3) 페이지로 넘어가고, 제목 줄은 `조회 › 상세` 경로였다(2026-09-19 §1.7).
두 항목을 비교하려면 목록과 상세를 오가야 했고, 상세에서는 목록이 사라져 「지금 몇 번째 무엇을 보고 있나」가 안 보였다.
상품모델링 화면 목업(대표담보 화면 목업 v1)은 항목을 고르면 목록이 왼쪽 패널로 줄고 오른쪽에 상세가 열린다.
유저는 이 틀을 **모든 메뉴의 목록 → 상세에 같은 방식으로** 쓰기로 했다(2026-10-28) — 같은 대상은 어디서나 같은 방식.

메뉴가 열세 개고 화면마다 머리 · 편집 상태가 따로 있어, 한 화면만 바꾸면 화면 간 일관성이 바로 깨진다. 그래서 여러 기능에 걸친 화면 뼈대다.

## 결정

1. **목록 → 상세는 한 화면이다.** 상세가 열리면 목록은 왼쪽 **목록 패널**로 줄고, 오른쪽이 상세다. 메뉴마다 같은 레이아웃 컴포넌트(`ListDetailLayout`)를 쓴다.
   - 패널은 **펼침 · 얇은 띠(접힘)** 둘. 접힘은 메뉴마다 기억한다. 칸이 많은 약관 편집기(조 목차 | 본문 | 오른쪽 패널)는 접어 두고 쓴다.
   - 패널 머리는 **L1 이름**(「담보약관 템플릿」) — 누르면 **목록 펼치기**(상세를 닫고 전체 목록으로).
2. **항목 탭.** 목록에서 고른 항목이 상세 맨 위에 탭으로 쌓인다. 탭을 눌러 오가며 비교하고, 탭마다 ✕ 로 닫는다. 현재 탭은 밑줄.
3. **편집은 한 탭만.** 편집 모드는 한 번에 한 탭에서만 켠다. 편집 중에 다른 탭으로 가도 초안은 남고 그 탭에 「편집 중」이 붙는다.
   다른 탭에서 「편집」을 누르면 「먼저 A 를 저장하거나 버리세요」. 저장은 지금처럼 한 번에 한다.
4. **보관.** 현재 항목은 URL 하나(`/documents/<id>` …) 그대로. 열어 둔 탭 목록과 패널 접힘은 브라우저(localStorage, 메뉴별)에 둔다 — 새로고침해도 남는다.
   편집 초안은 그 브라우저 탭의 메모리에만 있다(새로고침하면 사라진다 — 지금과 같다).
5. **제목 줄.** 상세 맨 위가 항목 탭 줄, 그 아래 제목 줄(현재 항목 이름). **경로에서 L1 마디가 빠진다** — L1 은 패널 머리가 맡는다.
   더 깊이 파고든 상세(상세2)만 `항목 › 상세2` 로 보인다.
6. **영역 탭이 있는 화면(상품)** 은 영역 탭을 제목 줄의 항목 이름 바로 오른쪽에 **세그먼트(버튼 묶음)** 로 둔다. 오른쪽 끝은 `HeadActions`.
   영역은 URL(`?tab=`)에 남고, 항목 탭마다 마지막으로 본 주소(영역 포함)를 기억한다. 탭 줄은 「항목 탭 한 줄 + 제목 · 영역 한 줄」.

임의 결정(2026-10-28, 유저에게 보고):

- 탭은 **최대 8개**. 넘치면 가장 오래 안 본 탭(현재 · 편집 중 탭 제외)이 닫힌다. 폭이 모자라면 탭 줄이 가로로 스크롤된다.
- 목록에서 이미 열린 항목을 누르면 **그 탭으로 간다**(새 탭을 만들지 않는다). 패널의 줄은 그 탭이 마지막으로 본 주소로 간다.
- **마지막 탭을 닫으면 전체 목록**으로. 현재 탭을 닫으면 오른쪽 이웃(없으면 왼쪽)으로.
- 목업의 「이전」 · 「다음」 버튼은 두지 않는다 — 패널 목록과 탭이 같은 일을 하고, 제목 줄 조작 줄(§1.9)이 길어진다.
- 패널 줄은 **이름(위, 진하게) + 코드(아래, 회색 고정폭) 두 줄 칸 하나**(§2 L1 「짝으로 다니는 두 열」). 검색칸(코드 · 이름) 하나를 두고 페이저는 두지 않는다 — 스크롤하고 아래에 「총 N건」. 열 필터는 전체 목록에만.
- 편집 중인 탭을 ✕ 로 닫으면 고친 것이 있을 때 「저장하지 않은 변경 사항이 있습니다」(EditShell 과 같은 확인).
- 좁은 폭(900px 미만)에서는 펼친 패널이 상세 위에 겹쳐 뜬다 — 상세 폭을 빼앗지 않는다. 접힘 기억은 같다.
- 약관 편집기 메뉴(보통약관 · 담보약관 템플릿 · 함수조항 · 동적표)는 고른 적이 없으면 패널이 접힌 채 시작한다 — 펼친 패널을 빼면 편집기가 세 칸 기준 폭(1100)에 못 미친다.
- 「새 ○○」(생성 화면)도 같은 틀 안에 열린다 — 패널은 남고 항목 탭은 생기지 않는다(아직 항목이 아니다). 제목 줄은 「새 ○○」.

## 이유

- **비교가 일이다.** 약관 템플릿 · 함수조항 · 담보는 비슷한 것을 나란히 놓고 만든다. 탭이면 A ↔ B 가 한 번 누름이고, 패널이 있으면 다음 것을 고르러 목록으로 나가지 않는다.
- **URL 은 하나로 둔다.** 열린 탭 전부를 URL 에 넣으면 주소가 길어지고 공유한 주소가 받는 사람의 탭을 덮는다. 현재 항목만 URL 이면 E2E · 링크 · 오류 좌표가 지금 그대로 닿는다.
- **편집을 한 탭으로 묶는다.** 여러 탭에 미저장 초안이 흩어지면 「어디를 저장 안 했나」를 사람이 기억해야 한다. 하나면 「편집 중」 표시 하나가 답한다.
- **L1 마디를 패널 머리로.** 패널이 이미 L1 이름을 들고 있는데 제목 줄 경로가 또 말하면 두 번 선다. 항목 이름이 곧 제목이면 탭 줄 바로 아래가 그 이름이라 읽기도 짧다.
- **영역 탭을 제목 줄로.** 「항목 탭 · 제목 · 영역 탭」 세 줄이 되면 본문이 밀린다. 영역은 항목 탭과 모양을 갈라(밑줄 ↔ 세그먼트) 두 탭이 섞여 읽히지 않게 한다.

## 버린 대안

| 안 | 버린 이유 |
|---|---|
| 지금처럼 상세 페이지 이동 + 경로 | 비교 · 다음 항목 고르기가 목록 왕복이다. 유저가 바꾸기로 결정 |
| 열린 탭을 URL 에 다 싣기(`?open=a,b,c`) | 주소가 길고, 공유 · 북마크가 받는 쪽 탭 목록을 덮는다. 새로고침 보존은 localStorage 로 충분 |
| 탭 상태를 서버(사용자 설정)에 저장 | 화면 상태일 뿐인데 DB · 서비스 경계가 생긴다. 기기마다 달라도 문제없다 |
| 여러 탭 동시 편집 | 미저장 초안이 흩어지고, 저장 · 충돌 · 버림 확인이 탭 수만큼 생긴다 |
| 탭을 옮기면 편집을 버림(확인 후) | 편집 중에 다른 것을 보며 고치는 것이 비교의 주 용도다 |
| Next.js `cacheComponents`(Activity 로 지난 화면 보존) | 앱 전체 캐시 모델이 바뀐다(`force-dynamic` 37곳 · 데이터 읽기 방식). 초안 보존은 편집기 쪽 보관으로 충분 |
| 병렬 라우트(`@list` 슬롯)로 전체 목록 표를 패널에 그대로 | 화면마다 슬롯 · 기본 페이지를 둘씩 늘린다. 패널은 코드 · 이름 · 검색이면 되므로 레이아웃이 요약 목록을 한 번 읽는다 |
| 영역 탭을 제목 줄 아래 밑줄 탭 그대로 | 탭 줄이 셋이 되고, 항목 탭(밑줄)과 영역 탭(밑줄)이 같은 모양이라 어느 쪽이 무엇인지 안 읽힌다 |
| 목업의 「이전」 · 「다음」 | 위 임의 결정 |

## 결과와 감수하는 비용

- 경로(§1.7)가 `항목 › 상세2` 로 짧아진다. 첫 마디가 내비 이름이던 규칙은 패널 머리로 옮긴다.
- 메뉴마다 `layout.tsx` 가 요약 목록(코드 · 이름)을 읽는다 — 상세를 볼 때도, 저장 뒤 `router.refresh()` 때도. 마스터 크기가 지금 수준이면 비용은 작다.
- 편집기마다 「편집 시작 전 잠금 확인 · 떠날 때 초안 보관」을 부른다(`useItemEdit`) — 새 편집기를 만들면 이것도 부른다.
- 초안 보관은 메모리라 새로고침 · 브라우저 탭을 닫으면 사라진다(지금과 같다).
- 관계정보는 상세 URL 이 없는 한 화면(그래프 패널)이라 이 틀 밖이다. 「상품담보명 규칙」(`/attributes/template`)은 L1 하위 탭이라 목록 그대로.
