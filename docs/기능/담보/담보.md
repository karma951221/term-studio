## 1. 한 줄

담보는 재사용되는 보장 단위의 **마스터**다 — 담보 › 세부보장 › 급부 3층 구조와 이름, 각 층의 값(기본값), 담보분류(기본 특약 그룹의 재료), 담보약관 템플릿 1벌을 소유한다.
상품 설계자가 상품에 탑재하기 전에 만들어 두고, 탑재된 뒤에도 구조를 고친다. 탑재 · 상품담보 · 담보속성 조합은 [[기능/상품/상품]] · [[기능/담보속성/담보속성]] 의 일이다.

## 3. 규칙

### 3.1 트리

- **담보 › 세부보장 › 급부 3층.** 단순 담보(각 1개)도 같은 3층의 최소 사례다. 구조는 마스터 소유이고 탑재한 모든 상품이 공유한다 (ADR-0002).
- **최소 구조** — 담보는 세부보장 1개 이상, 세부보장은 급부 1개 이상. 생성이 세부보장 1 · 급부 1 을 함께 만든다(원자적). 마지막 하나의 삭제는 관리자도 거부한다.
- **이름** — 담보명은 전역 유일, 세부보장명 · 급부명은 형제 사이에서 유일(다른 부모 아래 같은 이름은 허용). 빈 이름은 저장 거부.
  이름은 뼈대 속성이다 — 값이 아니라 스냅샷 대상이 아니고, 이름 수정은 탑재 여부와 무관하게 편집자가 한다.
- **급부명은 선택 값이다** (2026-10-31 사용자 결정 — 구현 2026-10-31) — 급부명이 비면(빈 글자로 저장) 어디서나 **세부보장명**으로 읽는다(`benefitDisplayName` — `nodesOf` · 자식 제공자 · 조립 스냅샷 트리가 같은 이름을 낸다): 동적표 행 머리([[기능/동적표/동적표]] §3.2) · 식의 `builtin.benefit.name`([[공통/기술/식언어]] §3) · 화면 표시(담보 카드 · 상품담보 값 화면 — 흐린 글자 + tooltip, 편집 입력칸은 placeholder 「비우면 세부보장명」). 세부보장명을 고치면 따라간다(복사가 아니라 읽을 때 대신한다). 형제 유일 검사는 적힌 급부명끼리만 한다(DB 유일 인덱스도 빈 이름을 빼는 부분 인덱스 — 마이그레이션 0040). 담보명 · 세부보장명은 그대로 필수다. 생성 화면이 급부명을 비워 보내면 빈 채로 만든다(안 주면 담보명 — 옛 기본값 그대로).
  — 왜: 급부 하나뿐인 세부보장에서 같은 이름을 두 번 적게 된다. 현행 시스템도 급부명이 없으면 약관세부보장명을 쓴다.
- **순서는 데이터** — 형제 순서가 곧 문면 수록 순서 · 반복 표 행 순서 · 집계 순회 순서다. 순서를 바꿔도 노드 키는 그대로다(§3.8).
- 세부보장 · 급부의 **부모 이동은 없다** — 값 행의 소속 이관 규칙이 없다.
- 담보명에 담보속성 값(기본계약 · 갱신형 …)이 들어가면 **경고**한다. 저장은 막지 않는다 — 담보속성은 탑재할 때 정한다.
- **담보코드** (2026-09-27) — `COV000001` 부터 **시스템이 채번**한다. 생성 입력에 코드 칸이 없고, 등록 뒤에는 바뀌지 않으며(이름 · 구조를 고쳐도 그대로), 전역 유일하다. 옛 시스템의 담보코드(COV000496)와 같은 모양 — 6자리를 넘으면 자르지 않고 늘린다.
  순번은 별표 · 공용조항과 같은 채번 순번(`code_sequences`, kind `coverage`)이고 오르기만 한다 — 지운 담보의 코드는 다시 태어나지 않고, 거절된 생성(빈 이름 · 중복 이름)은 순번을 쓰지 않는다. 기존 담보는 마이그레이션 0015 가 **만든 순서대로** 채웠다.
  — 왜: 목록 1열은 코드다([[공통/화면/디자인원칙]] §2 L1)이고, 상품모델링의 탑재 표가 담보를 코드로 찾는다([[기능/상품/상품]] §4.5). 사람이 코드를 고르면 중복 · 형식 검사와 개명 규칙이 생긴다.
- **담보분류** (2026-10-17 사용자 결정, [[기능/상품/결정/ADR-0090-특약그룹-담보분류기본그룹-상품사용자그룹]] — 구현 2026-10-17) — 담보는 열거형 **「담보분류」** 의 값 하나를 고른다(필수). 값은 상해 · 질병 · 비용손해 · 배상책임 · 재물손해이고, 열거형이라 값은 데이터로 늘린다. 코드가 그 열거형을 가리킨다(시드 기준 E0009 — [[기능/열거형/열거형]] §3.1).
  담보분류가 **기본 특약 그룹**이다 — 상품이 사용자 그룹에 넣지 않은 이 담보의 특약 · 블록은 이 값의 그룹에 묶이고, 그룹 제목은 값의 「그룹 제목」 문자 필드, 기본 순서는 값 순서다([[기능/상품/상품]] §3.7).
  뼈대 칸(`coverages.category`, 값 코드 — null = 미입력)이라 값 폼의 필드가 아니고 **스냅샷 대상이 아니다** — 탑재한 상품은 지금 담보의 담보분류를 따르고, 바꾸면 그 담보를 기본 그룹으로 쓰는 모든 상품의 책자가 바뀐다. 상품이 묶음을 바꾸는 길은 상품의 사용자 그룹 하나다.
  — 왜: 기본 그룹을 정하는 값이라 폼 필드로 두면 탑재 때 스냅샷되어 상품담보 값 화면에서 고칠 수 있게 되고(ADR-0002), 담보분류를 고쳐도 탑재된 상품은 옛 값에 남는다 — 이름 · 구조처럼 「지금 마스터를 따르는」 뼈대다.
  검사(`setCoverageCategory`): 비우면 `notEntered` 「담보분류를 고르세요」, 열거형에 없는 값이면 `brokenRef`. 열거값을 지우면 코드가 남아 「없는 값 V03」 — 담보 화면 · 조립 오류가 드러낸다([[기능/열거형/열거형]] §3.2). 편집자가 한다.
  참조 그래프에는 담보 → 담보분류 열거값 간선 `category`(라벨 「담보분류」)가 선다.
  옛 「특약 그룹」 칸(`coverages.special_group` · 열거형 E0008)은 없앴다 — 담보분류가 대신한다(ADR-0080 번복).
- **담보 자체 상태(미사용 · 적용 · 확정)는 없다.** 「고쳐도 되는가」는 탑재 상품담보 수가 답한다 — 화면에서는 저장 확인이 보인다 (ADR-0075).

### 3.2 구조 정정 — 편집 하나 · 저장 시 영향 확인

생성 뒤에도 구조를 고친다. **탑재 여부와 상관없이 담보 상세의 `편집` 하나에서** — 카드 위 조작(+ 추가 · ↑↓ 순서 · ⊖ 빼기 · 이름 인라인)이 초안에 담기고
담보명 · 값과 함께 저장 한 번에 들어간다 (ADR-0075). 갈림은 입구가 아니라 저장이 한다 — 「이미 저장된 값 · 참조를 없애는가」(ADR-0019)와 탑재 상품담보 수(계산, 상태 아님).

| 변경 | 누가 | 저장할 때 |
|---|---|---|
| 이름 | 편집자 | 확인 없음. 탑재 스냅샷의 이름도 같은 트랜잭션에서 따라온다 |
| 추가 · 순서 | 편집자 | 미탑재면 확인 없음. **탑재됐으면** 먼저 영향 확인(탑재 상품담보 목록) — 「구조 바꾸고 저장」. 추가 노드는 탑재분에 **미입력 자리**로 생기고, 순서는 탑재 상품의 조문 수록 순서가 따라 바뀐다 |
| 삭제 | **관리자만** | 파괴적 — 늘 먼저 영향 확인(「세부보장·급부 N개 삭제하고 저장」). 마스터 · 탑재 스냅샷 값 행이 연쇄 삭제된다. 영향이 비어도 절차는 같다 |

- 편집자가 삭제를 섞어 저장하면 **서버가 거부**한다 — 「세부보장 · 급부 삭제는 관리자만 할 수 있다」 배너. 화면 숨김이 아니라 서버 거부다 (ADR-0019).
- 영향 = 소실될 마스터 값 행 수 · 깨질 문면 참조 · 함께 지워질 하위 · 탑재 상품담보별 스냅샷 소실 행.
- **확인 전엔 아무것도 저장하지 않는다.** 확인하면 담보명 · 구조 · 탑재 스냅샷 동기화(추가 = 미입력 · 삭제 = 값 행 삭제 · 이름 · 순서 갱신) · 값이 **한 트랜잭션**이고,
  어느 단계가 거부되면(값 쓰기 포함) 전부 롤백 · 편집 유지 + 배너. 저장 전에 계획 전체를 메모리에서 돌려 부분 저장을 막는다 (ADR-0075 · ADR-0002).
  — 왜: 영향은 초안이 정해진 뒤에야 정확하다(초안 기준 소실 행). 편집 전에 영향을 보이던 별도 「구조 편집」 화면은 입구를 둘로 나눴다 (§6.2).
- **형제 이름 규칙은 최종 트리 하나다** — 저장 뒤 트리에서 같은 부모 아래 이름이 겹치지 않으면 된다. 그래서 형제 이름 A↔B 맞바꾸기, ⊖ 로 뺀 형제의 이름을 새 노드 · 개명에 다시 쓰기가 된다. 다시 쓴 이름의 노드는 **새 노드**다 — 지운 노드의 값 · 탑재 스냅샷 값은 따라오지 않는다(삭제 영향 확인에 이미 실린다). 편집기의 이름 옆 표시(빈 이름 · 형제 중복)와 서버 검사가 같은 규칙이다.
  — 왜: 전에는 서버가 이름 → 추가 → 삭제를 한 단계씩 검사해, 화면은 저장 버튼을 켰는데 서버가 중간 상태의 이름 충돌로 거부했다(「지운 형제 이름 재사용 = 거부」, 점검 2026-09-27 H2 ③). 적용은 ⓪ 바뀌거나 지워질 노드의 이름을 자리표로 비움 → 추가 → 삭제 → 새 이름 → 순서라, 중복 거부는 최종 트리에서도 겹칠 때뿐이다 (`applyStructurePlanTo`).
- 담보약관 템플릿이 있어도 구조 수정을 막지 않는다. 사라진 노드를 가리키는 반복 · 슬롯 · `@노드` 조건은 **오류 상태**로 드러나고 문면에서 고친다 (ADR-0075).
- **담보 삭제** — 관리자만. 영향: 하위 세부보장 · 급부, 마스터 값 행, 담보약관 템플릿, 탑재 상품담보(마스터를 잃는다) (ADR-0019).

### 3.3 값 — 노드 × 마스터 필드

- 값 자리는 **노드 × 그 레벨의 마스터 필드**다. 부착 · 노출여부는 없다 — 그 레벨 필드는 모든 노드에 늘 있고, 안 쓰는 항목은 미입력으로 둔다 (ADR-0037).
  단 마스터가 **선택 필드**로 정한 것(지급률)은 값이 없으면 카드에 안 보이고 미입력으로 세지 않는다 — 편집 중 급부 이름 줄의 「지급률 ⊕」로 더한다([[기능/마스터/마스터]] §3.4 · §3.6).
- 지금 레벨별 필드 ([src/domain/master/catalog.ts](../../../src/domain/master/catalog.ts)) —

  | 레벨 | 폼 · 필드 |
  |---|---|
  | 담보 | 특성 **가입금액** `insured_amount`(여는 폼 — 아래, 2026-10-31 구현). 보험금명(`coverage_basic.claim_name`)은 2026-10-21 없앴다 — 조문의 보험금 이름은 담보약관에 글자로 쓴다([[기능/담보/결정/ADR-0091-보험금명삭제-담보약관에글자로]]) |
  | 세부보장 | 없음 |
  | 급부 | 보험금지급 `pay`(지급률 — 선택 필드, 안 적으면 100%) · **감액** `reduction` · **면책** `exemption` (여는 폼 = 특성 — §3.4) · 특성 **정액표** `fixed_table`(마스터 소유, 2026-10-31 구현) · **체증**(TODO) |

- **지급률 기본 100 · 선택** (2026-10-21) — 지급률(`pay.rate`, %)은 급부 값이고 **안 적으면 100%** 다. 미입력(완결성)으로 세지 않고, 지급률을 읽는 곳(동적표 셀 비율 — [[기능/동적표/동적표]] §3.4)은 값이 없으면 100 으로 읽는다. 칸은 늘 보이지 않는다 — 급부 이름 줄 오른쪽 「지급률 ⊕」(§3.6).
- **가입금액 — 담보 레벨 값 하나(금액 여러 개)** (2026-10-31 사용자 결정 — 구현 2026-10-31, 여는 폼 `insured_amount` · 필드 `amounts: table{ 금액(원): number }`) — 필요한 담보에 붙이는 담보 레벨 특성이다(통합치료비 전용이 아닌 담보 일반 사실 — 담보 카드 「특성 ⊕」 › 가입금액). 금액은 1 이상 정수(원) · 같은 금액 두 번 거부(`checkInsuredAmounts`), 순서는 묻지 않고 읽을 때 오름차순(`insuredAmounts`). 마스터 값 = **가능한 가입금액 전체**(급부 정액표의 가입금액 열과 같다). 탑재 때 상품담보로 복사되고(상품 소유 — [[기능/상품/결정/ADR-0097-필드소유-마스터소유-상품소유]]) 상품이 운영하지 않는 금액을 지운다 = **운영 가입금액**. 동적표 정액형 표는 상품담보의 운영 가입금액만큼 오름차순으로 캡션 + 표를 찍고, 정액표에 없는 금액이 상품담보에 있으면 조립 오류다([[기능/동적표/동적표]] §3.7).
  — 왜: 가능한 금액과 운영 금액은 같은 값의 마스터 · 상품 판이다 — 칸을 둘로 나누면 같은 사실을 두 곳에서 맞춘다.
- **면책여부 필드는 없다** (2026-10-21) — 면책 여부는 급부에 면책 특성(`exemption`)이 붙었는지로만 정한다(기본 아니오). 식은 `exist(exemption.months)` 로 읽는다. 옛 `pay.exempt` 값 행은 마이그레이션 0033 이 지웠다.
  — 왜: 같은 뜻의 칸(면책여부 = 예)과 특성(면책 폼)이 따로 있으면 둘이 어긋난다.

- **미입력은 상태다.** 기본값은 프리필로만 들어오고 저장해야 명시 값이 된다. 명시 값 → 미입력으로 되돌리는 「값 비우기」가 있다 (ADR-0004).
- 마스터 값을 고쳐도 이미 탑재된 상품담보의 값에는 **소급되지 않는다** — 새로 탑재하는 분부터 반영된다 (ADR-0002).
  단 **마스터 소유** 값은 복사되지 않아 고치면 탑재한 상품에 바로 반영된다(2026-10-31 사용자 결정 — 구현 2026-10-31, 폼 표식 `owner: "master"`, [[기능/상품/결정/ADR-0097-필드소유-마스터소유-상품소유]]). 마스터 소유 = 급부명 · 구조 · 담보분류(원래 뼈대) · 유형 특성(급부 정액표 · 체증 · 담보 단서문구), 상품 소유 = 지급률 · 감액 · 면책 · 운영 가입금액 · 담보속성([[기능/상품/상품]] §3.4).
- 값 쓰기는 타입 검사 + 경로별 규칙(`validateSlotValue`)을 탄다 — 담보 마스터와 상품담보 스냅샷이 같은 검사다.
- **구조 모양에 따라 더 묻는 값은 없다** — 세부보장이 하나든 여럿이든 급부가 받는 값은 급부 레벨 폼뿐이다. 지급사유 · 가입금액 기준 문구는 담보약관(문면) 몫이다.
  — 왜: 문구를 값으로 받으면 상품마다 다시 적게 된다. 문구는 문면이 소유한다.

### 3.4 급부 특성 — 감액 · 면책 · 정액표

급부 레벨 **시스템 시드 폼** 셋이다 — 감액 · 면책 · 정액표(2026-10-31 구현) · 체증(2026-11-01 기획 — 미구현). 폼 값이라 스냅샷(정액표는 마스터 소유라 빼고) · 값 저장소 · 식 참조를 그대로 탄다 (ADR-0065).

- **담보유형은 두지 않는다 — 특성 조합이다** (2026-10-31 사용자 결정 — 구현 2026-10-31, [[기능/담보/결정/ADR-0096-담보유형없음-특성조합]]) — 체증형 · 주요치료비 · 통합치료비 같은 「담보 유형」을 열거 값으로 두지 않는다. 통합치료비 = 담보 「가입금액」(§3.3) + 급부 「정액표」, 주요치료비 = 담보 「단서문구」(지금은 동적표 글 인자 — 특성으로 옮길지는 구현 때), 체증형 = 급부 「체증」(TODO). 목록 걸러보기 · 안내용 이름이 필요하면 붙은 특성으로 계산한 꼬리표다.
  — 왜: 유형은 겹친다(주요치료비 체증형 = 합성) — 열거 값이면 조합 값이 는다. 어떤 표를 찍나(문면이 고른 동적표 정의) · 데이터(특성) · 어긋남(검사) 자리가 이미 있어 유형 칸을 더하면 같은 사실을 두 곳에서 맞춘다.
- 유형 특성(정액표 · 체증 · 단서문구)은 **마스터 소유**다(폼 표식 `owner: "master"`) — 탑재 때 복사하지 않고 상품에서 읽기 전용이다([[기능/상품/결정/ADR-0097-필드소유-마스터소유-상품소유]], 구현 2026-10-31). 감액 · 면책은 상품 소유(아래 「상품별 값」).

- **여는 폼** — 급부에서 폼을 **열지 않음 = 그 특성 없음.** 연 폼의 자리만 완결성 · 식에 잡힌다. 열었다가 닫으면 그 값을 지운다 (ADR-0065 §4). 별도 「감액 여부」 필드는 없다.
  화면 (2026-10-21): 열지 않은 특성은 자리가 없다 — 읽기 모드엔 아무것도 안 보이고, 편집 모드엔 급부 박스 안 라벨 행 **「특성 ⊕」 하나**. 누르면 메뉴에서 감액 · 면책 · 정액표(2026-10-31) 중 고르고, 고른 특성 박스가 그 아래 생긴다. 이미 붙은 특성은 메뉴에서 빠지고, 다 붙었으면 ⊕ 가 잠긴다. 특성 박스는 **왼쪽 위 ⊖** 로 닫는다(값을 지운다). 담보 카드도 같은 문법으로 「가입금액」 특성을 붙인다(§3.3).
  — 왜: 「감액 없음」과 「아직 안 적음」(ADR-0004)을 필드 하나 없이 가른다. 구간이 없는 것을 곧 100% 로 읽으면 아직 안 적은 감액이 조용히 100% 로 나간다.
- **감액** `reduction` —

  | 필드 | 타입 | 규칙 |
  |---|---|---|
  | `periods` 구간 | `table{ 기간: enum 「감액기간」, 지급률: percent }` | 사람은 **끝 경계만** 적는다 — 한 행 = 「직전 경계 ~ 이 경계 미만」(반열림: 경계 달은 다음 구간에 든다), 첫 행 시작은 **보장개시일**(계약일, 갱신형은 최초계약일). 기간은 열거형 「감액기간」(E0010)의 값 하나를 고른다(저장은 값 코드 `V03`). **엄격 오름차순**(열거 순서 — 같은 값 두 번은 중복 · 앞 순서는 역전 거부). 열고 0행이면 저장 거부 |
  | `after_rate` 이후 지급률 | 정수 0~100 | 마지막 경계 이후 지급률. 기본 100 — 표에 「이후 100%」 행을 적지 않는다 |
  | `new_only` 신규계약만 적용 | boolean | 기본 켬 |

  — 왜: 끝 경계만 적으니 구간 사이 공백이 생길 수 없고, 겹침 검사가 「엄격 오름차순」 하나로 준다. 반열림은 실물 조문의 세는 법(시작일 포함 · 계약해당일 전일까지)과 같다.
- **경계 = 열거형 「감액기간」 값** (2026-10-31 사용자 결정 — 구현 2026-10-31) — 경계를 개월 수로 직접 적지 않고 열거형 「감액기간」(E0010 — 초기값 90일 V01 · 180일 V02 · 1년 V03 · 2년 V04, 열거형이라 값을 더한다 — [[기능/열거형/열거형]] §3.1) 중 하나를 고른다. 구간이 여럿이면 구간마다 고른다. 구간 비율 · 이후 지급률 · 신규계약만 적용은 그대로다. 「엄격 오름차순」은 **열거 값 순서**로 견준다(같은 값 두 번 · 역전 거부 — `checkReductionPeriods`). 열거형에서 지운 값이 남으면 저장 검사 brokenRef 「없는 값 V09」(값 폼 · 조립 오류). 표 열 타입 `enum`(`TableColumn.enumCode`)이 이 자리를 만든다 — 코드가 가리키므로 E0010 은 지울 수 없다(「담보분류」와 같은 결). 기존 개월 수 데이터는 마이그레이션 0039 가 시드 값으로 옮긴다(3 · 6 · 12 · 24 → V01 ~ V04, 그 밖은 구간 값 행을 지워 미입력으로 드러낸다).
  — 왜: 단위가 섞인 경계(개월 · 일)를 견주거나 표기를 바꿀 일 없이 순서와 문구(「90일」 · 「1년」)가 목록에서 나온다. 실물에 90일 경계가 있다(뇌혈관질환진단비II — 90일 10% · 1년 50%).
- **「이후 지급률」은 기본 숨김** (2026-09-27) — 값이 100(기본값)이면 편집 화면에서 칸 대신 감액 카드 안의 작은 링크 「이후 지급률 바꾸기」만 보이고, 누르면 칸이 펼쳐진다(다시 접기 없음). 읽기 모드는 100 이면 표시하지 않는다. 저장된 값이 100 이 아니면(또는 그 자리에 오류가 있으면) 숨기지 않는다. 숨긴 동안에도 프리필 규칙은 같다 — 숨긴 채 저장하면 100 이 명시 값으로 실린다(디자인원칙 §9.1 「저장이 곧 확인」). 마스터 필드 속성 `hiddenByDefault` 로 표시하고 폼 렌더가 그걸 본다 — 지금은 이 필드 하나에만 붙는다.
  — 왜: 현업에서 이후 지급률은 거의 늘 100 이라 칸이 보이면 매번 확인할 거리만 늘고, 드문 예외는 링크 한 번으로 연다.
- 경계는 날짜가 아니다 — 월말 · 윤년의 실제 경과일은 표가 아니라 약관 조문(보장개시일 · 계약해당일)이 정한다. 표는 경계 글자만 찍는다(열거값 표시 글자 「90일」 · 「1년」).
- 지급률은 **급부 지급률(`pay.rate`)에 곱하는 비율**(% 정수 0~100, 0 = 그 구간 지급 없음)이다 — 표에 찍히는 비율은 `pay.rate` × 감액 지급률 / 100 이다. 표시 문구(「보험가입금액의 n%」 · 머리글 「계약일부터 1년경과시점 전일 이전」)와 표에 찍는 곱은 동적표([[기능/동적표/동적표]] §3.4, 구현 2026-10-18) 몫이다.
  — 왜: 곱이 없으면 체증형 · 레퍼런스 표(지급률 20% × 감액 50%)를 만들 수 없다. 소수가 나오면 한 자리까지 그대로 찍고 반올림하지 않는다.
- **면책** `exemption` — `months` 기간(개월 수, 입력 칸 옆에 「n년 n개월」 해석) · `age15_only` 15세 이상만 적용(기본 끔) · `new_only` 신규계약만 적용(기본 켬). 표가 아니다 (ADR-0065 §6).
  담보약관 템플릿은 면책 특성이 있으면 암보장개시일 문구를, 그 안에서 `age15_only` = 예면 15세 단서를 낸다(템플릿 IF — 시드 구현 2026-10-27, [[기능/상품/상품]] §3.9). 정의 항 밖 「○○보장개시일 이후(에)」 어구도 면책 특성이 없으면 무면책 원문 문형으로 빠진다(같은 날). 무효 항 · 부활 문장의 보장개시일은 후속.
- **표 입력**(`table` 필드) — 첫 행 머리글, 셀 타이핑, 엑셀 붙여넣기(포커스한 셀부터 덮고 모자란 행은 늘린다 · 줄 → 행 · 탭 → 열 · 첫 줄이 머리글과 같으면 버림 · `%` 제거), 행 추가 · 삭제. 해석 실패 셀은 「n행 기간: '…' 를 해석할 수 없습니다」로 저장 거부. `period` 열은 셀 아래 해석 힌트(`1Y` → 「1년」 — 지금 쓰는 시스템 폼에는 없다).
  행별 파생 범위 칸 · 붙여넣기 전용 영역 · 「감액 없음으로」 버튼은 두지 않는다 — 표 + 토글 + 힌트가 같은 정보를 준다.
  **감액 표의 기간 칸은 열거값 고르기**(`enum` 열 — `<select>`, 2026-10-31 구현) — 붙여넣기는 값 코드(`V03`)나 표시 글자(「1년」)를 그 열거형에서 코드로 푼다. 열거형에 없는 글자(「3M」)는 해석 실패, 지워진 값의 코드(`V09`)는 그대로 두어 저장 검사가 「없는 값」으로 드러낸다.
- **상품별 값** — 탑재 때 스냅샷으로 복사되고 상품담보에서 값만 바꾼다. 구간을 늘리고 줄이는 것, 감액 · 면책 특성을 붙이고 떼는 것(특성 없음 = 무면책 · 감액 없음)도 값 편집이다. 어느 급부가 있느냐(구조)는 마스터 소유다 (ADR-0002). 화면은 상품담보 값 화면(구현 2026-10-27, [[기능/상품/상품]] §3.4 · §4.8).
- **정액표** (2026-10-31 사용자 결정 — 구현 2026-10-31, 여는 폼 `fixed_table` · 필드 `grid`(타입 `grid` — 격자 하나 `FixedGrid{ columns, rows[{ cells, amounts }] }`) · **마스터 소유** `owner: "master"`) — 통합치료비의 치료항목별 정액. **화면 이름은 「통합치료비」** (2026-11-01 사용자 결정 — 미구현, 지금 화면은 「정액표」) — 코드 키 `fixed_table` · 저장 데이터는 그대로다. 급부에 붙는 특성(여는 폼)이고 저장처는 담보 마스터다(상품담보에서는 읽기 전용 — ADR-0097). 격자 하나:

  | 부분 | 규칙 |
  |---|---|
  | 글자 열 | 개수 · 머리 이름을 사용자가 정한다(1개 이상 · 머리 비지 않음). 새 정액표 기본 `분류 · 치료항목 · 지급횟수` 3열 |
  | 행 | 치료항목 한 줄(1행 이상) — 급부마다 행 집합이 달라도 된다. 글자 칸 수 = 글자 열 수 |
  | 가입금액별 정액 | 담보 가입금액(§3.3)의 금액마다 한 열(키 = 원 단위 정수) · 원 단위 정수(0 이상) · **공란 저장 거부** — 열이 하나는 있어야 한다 |

  검사는 `checkFixedGrid`(담보 저장 · 값 폼 모두). 입력 부품은 `GridInput`(글자 열 머리 타이핑 · 열 ⊕/⊖ · 가입금액 열 ⊕(금액 입력)/⊖ · 행 ⊕/⊖ · 셀 타이핑) — 지금은 담보 상세의 급부 카드에 선다(§5 모달 자리는 미결).

  현행 시스템 지급금액표 기획(2026-10-31 대조)의 「세트」(1. 상해로 인한 경우 / 2. 상해 이외의 사유로 인한 경우)는 **급부**로 대신한다 — 세트 개념 · 세트별 「감액 적용 여부」 칸은 없다. 상해 급부에 감액이 없으면 그 급부 표는 저절로 열 하나다. 표로 펼치는 일(캡션 · 감액 열 금액 · 표기)은 동적표 정액형 표([[기능/동적표/동적표]] §3.7) 몫이다.
  — 왜: 치료항목별 정액은 담보 트리 어디에도 없다. 급부에 붙이면 세트가 급부가 되어 감액도 급부마다 이미 있는 특성으로 갈린다.
- **체증** (2026-11-01 사용자 결정 — **미구현**, 여는 폼 가칭 `escalation` · **마스터 소유** `owner: "master"`) — 경과기간 · 진단후 연차에 따라 지급비율이 늘어나는 급부(간병인사용 입원일당(체증형) · 주요치료비(체증형)). 급부에 붙는 특성이고 저장처는 담보 마스터다(ADR-0097).

  | 필드 | 타입 | 규칙 |
  |---|---|---|
  | 구간 | 표 `{ 구분: 글, 비율: 수 }` | 행 추가 · 삭제 자유, 행 순서 = 표에 찍히는 순서. **0행이면 저장 거부** |
  | 구분 | 글 + 칩 | 사용자가 직접 적는다(「2대질환 진단후 1차 연도」 · 「〔(최초)계약일〕부터 5년경과시점 전일 이전」). 조건식은 넣지 않고 **칩 `(최초)계약일` 하나만** — 입력 폼 위 글자 버튼 「(최초)계약일」을 누르면 커서 자리에 들어간다. 조립 때 그 상품담보가 갱신형이면 「최초계약일」, 아니면 「계약일」 |
  | 비율 | 수(배수) | 1 · 1.2 · 1.5 · 2 처럼 적는다. 비면 저장 거부 |

  — 왜 칩 하나인가: 구분 글이 조건으로 달라지는 곳은 「(최초)계약일」 어구뿐이다 — 표 입력 칸에 조건식 편집기를 넣는 것보다 칩 하나가 쉽다.
  — 왜 마스터 소유인가: 정액표 · 단서문구와 같은 유형 특성이다(ADR-0097 그대로).
- **표에서** ([[기능/구분자/구분자]] §3.7) — 체증 급부는 구분 수만큼 행이 늘고 행 머리 = **「급부명(구분)」**(급부명이 비면 세부보장명 — 「2대질환 주요치료비(2대질환 진단후 1차 연도)」). 셀 = 지급률 × 비율 × 감액비율. 열은 감액 구간뿐이다. 체증 표를 따로 두지 않고 보험금 지급금액표 한 쌍에 합친다.
- **회차 체증은 체증 특성이 아니다** — 수술비(25%체증형)처럼 회차마다 위험률이 따로인 담보는 **회차마다 급부 하나**(「뇌혈관질환 1회차 수술시」 지급률 100 · 「2회차」 125 · …)로 모델링한다 — 지금 지급금액표 그대로. 간병인사용 plus(체증형 아님)도 급부 셋(8시간 이상 / 8시간 미만 · 7만원 이상 / 8시간 미만 · 7만원 미만)으로 쓴다.
- **시스템 폼 잠금**(키 · 레벨 · 시스템 필드 삭제 · 타입 변경 불가) — `system` 표식만 있다. 폼을 화면에서 편집하는 경로가 MVP 에 없어 잠금 검사는 **미구현** (ADR-0065 §3).
- **식이 읽는 길** — 구분자가 폼 값을 투영한다: 급부 `감액여부 = exist(reduction.periods)` · `면책여부 = exist(exemption.months)` 같은 투영과 세부보장 · 담보의 `any(급부 …)` 집계를 **관리자가 필요할 때 만든다** — 시드에는 담보약관 보장개시일 정의 항이 읽는 셋만 둔다: 담보 「면책 있음」 `exist(exemption.months)` · 급부 「15세 이상만 면책」 `exist(exemption.months) and exemption.age15_only` · 담보 「15세 이상만 면책 있음」 `any(「15세 이상만 면책」)` (2026-10-27 — 감액 투영은 원문이 읽지 않아 두지 않는다, ADR-0065 §5).
  담보약관 조건식은 `감액여부@<노드>` 로 세부보장 · 급부 하나를 가리킨다 — 구분자 · 조건식 쪽 규칙은 [[기능/구분자/구분자]] · [[기능/문면/문면]]. 저장은 노드 키 경로다 — 소스 `D0007@01.2`, 화면 「세부보장 01 · 이름 › 급부 2 · 이름 › 구분자」(§3.8).

### 3.5 문면과 이어지는 곳

- 담보는 **담보약관 템플릿 1벌**을 소유한다(없어도 된다 — 문면 없는 담보는 조립에서 문서를 내지 않는다). 담보 상세 화면에는 담보약관 템플릿이 없다 — **담보약관 템플릿 메뉴**가 입구다 (2026-09-27, §6.2).
  만들기는 그 목록 제목 줄의 `+` → 「새 담보약관 템플릿」에서 **아직 템플릿이 없는 담보**를 고른다(`COV… 담보명`) → 조문 편집기로 ([[기능/문면/문면]] §4).
- **심사형만 다른 담보는 담보 하나 · 담보약관 하나** (2026-10-05 사용자 결정) — 일반심사형 · 통합간편심사형 같은 심사형 변형을 담보로 나누지 않고 재사용한다. 심사유형별 문구 차이는 담보약관 조건식으로 쓴다(예: 기왕증 문구 때문에 일반심사형에만 「진단확정된」). 상품담보명의 심사형 표기는 작명이 붙인다([[기능/담보속성/담보속성]] §3.4 — **미구현**).
  — 왜: 심사형마다 담보를 두면 같은 담보약관이 심사형 수만큼 되풀이되고 고칠 곳도 그만큼 는다.
- **조연결 = 같은 자리 — 절 형태에서는 제1절을 바꾼다** (2026-10-05 ~ 2026-10-07, [[기능/조립산출/결정/ADR-0082-제1절-자동판정-준용하기-독립특약]] 결정 1 · 15 — **미구현**) — 담보약관 조의 조연결은 대응 보통약관의 같은 자리 조를 가리킨다. 기본계약 하나(케이스 1)면 그 조를 대치하고, 기본계약 2+ · 독립특약(절 형태)이면 블록들이 연결한 템플릿 조를 시스템이 판정한다 — 그래서 담보 저작자의 조연결이 그 담보를 탑재한 상품의 제1절을 바꾼다. 조연결을 바꿔 저장하면 탑재 상품마다 판정 변화를 확인 카드로 본다([[기능/문면/문면]] §3.8).
  저작 기준 — ① 모든 블록에 걸려야 할 항은 담보약관마다 갖게 쓴다(연결 조의 제1절 내용은 블록에서만 나온다) ② 블록끼리 같게 판정받을 항은 같은 함수조항 · 같은 옵션 · 인자로 쓴다 ③ 보장 소멸 조는 계약 소멸 조에 연결하지 않는다(경고) ④ 준용하기 옵션 조는 함께 탑재될 담보가 모두 연결해야 옵션이 작동한다. 정본은 [[기능/문면/문면]] §3.10.
- 담보약관의 **공용조항 옵션은 담보 마스터 안에서 다 정한다** ([[기능/상품/상품]] §3.6). 미결정 옵션은 문면 저장 검사가 잡는다 — 담보 상세 헤더에는 배지가 없다.
- **반복 표** — 담보약관 템플릿의 표는 「세부보장마다」 · 「세부보장 › 급부마다」 행을 반복할 수 있고, 행은 이 트리의 순서 · 노드를 그대로 따른다. 세부보장 · 급부를 더하면 표가 따라온다 (ADR-0070 결정 6 · 10).
  문장 반복(`inlineFor`)은 세목 선택지 · 목록 · 합집합 원천 인라인 반복이다([[기능/문면/결정/ADR-0088-조제목인라인-인라인반복-반복비었을때칸]], 2026-10-16 구현) — 담보 트리 원천 문장 반복은 그 범위 밖(저장 오류). 블록 반복(`forBlock`)은 세목 선택지 · 열거 목록 원천에 더해 담보 트리 원천 「세부보장마다」 · 「세부보장 › 급부마다」를 돈다 — [[기능/담보/결정/ADR-0087-담보노드키-키경로참조-함수조항인자연결]] 결정 5([[기능/문면/문면]] §3.7).
- 표 행 · 셀의 **정체는 노드**(노드 키)다 — 이름이 같아도 다른 세부보장 · 급부면 다른 행이고, 병합하지 않는다.
- **최초지급금액표**(감액 구간으로 경계 합집합 표를 만드는 동적 표)는 [[기능/동적표/동적표]] 로 구현됐다(2026-10-18 — 담보약관 문면의 `dynTableRef` 가 이 담보의 급부 · 감액 값으로 펼친다, 담보 화면에는 없다). 편집값으로 그리는 실시간 산출 표 · 구조 판별(세부보장 1개 = A · 세부보장 여럿에 급부 하나씩 = B · 그 밖 = C → 문면 구분 배치 초기 제안)은 **MVP 밖**이다 ([[QA/인수기준]] MVP 범위).
  구조 유형(A/B/C)을 사람이 고르는 입력은 두지 않는다 — 판별은 트리 모양에서 하고 저장하지 않는다.

### 3.6 중첩 카드 — 담보 ⊃ 세부보장 ⊃ 급부

- 담보 마스터 화면은 **카드를 겹쳐 담는다** — 담보 카드 ⊃ 세부보장 카드 ⊃ 급부 카드. 카드마다 **이름 + 그 노드 레벨의 마스터 값 폼**. 담보명은 담보 카드의 이름이다(따로 기본정보 영역이 없다).
  값 폼은 **카드 본문에 바로 선다** (2026-09-27) — 노드 카드가 이미 테두리라 폼마다 상자(「담보 기본」 상자 등)를 두르지 않는다. 한 카드에 폼이 둘 이상 보이면(급부 — 보험금지급 + 감액) 폼마다 작은 제목 한 줄만.
  — 왜: 「담보 기본」 상자가 담보 카드와 같은 레벨인데 한 겹 더 싸여 있었다(사용자 피드백 2026-09-27). 상품담보 값 화면도 같다.
  필드가 없는 레벨(담보 · 세부보장)은 폼 자리가 없다. 급부 카드 안의 감액 · 면책은 특성(여는 폼)이다 — 없으면 자리가 안 보이고, 편집 모드에서 「특성 ⊕」로 더한다(§3.4).
- **배치** (2026-09-27 · 2026-10-21) — 담보 카드 본문은 **라벨 열 하나**다: 「담보」(이름) · 「담보분류」 · (편집) 「세부보장 ⊕」가 같은 라벨 열에 서서 입력칸이 한 세로줄에서 시작한다(담보 카드는 머리 줄이 없다). 그 아래 세부보장 카드가 **그리드**(넓으면 2열 · 좁으면 1열)로 선다. 급부 카드는 제 세부보장 카드 안에 쌓인다. 세부보장 · 급부 카드 머리는 작은 레벨 라벨 + 이름 한 줄. 레벨 라벨은 노드 키다 — 「세부보장 01」 · 「급부 1」(§3.8).
  급부 카드 머리 줄 오른쪽에 **「지급률 ⊕」** — 누르면 그 자리에 「지급률 [__]%」 칸이 열리고 옆 ⊖ 로 닫으면 값을 지운다(= 100%). 값이 있으면 열린 채 보인다. 읽기 모드는 값이 있을 때만 「지급률 n%」. 「미입력」 배지는 없다.
- **접지 않는다** (2026-09-27) — 모든 카드가 늘 보인다. 미입력 개수 · 입력률 카운트를 두지 않는다(화면 편집 원칙 2026-09-15).
- **편집 모드의 구조 조작 — 「라벨 ⊕」 → 그 아래 박스, 박스 왼쪽 위 ⊖** (2026-10-21, 현행 모델링 화면과 같은 규칙 — 모든 단계에 같다) — 담보 본문의 라벨 행 「세부보장 ⊕」를 누르면 세부보장 박스가 목록 끝에, 세부보장 박스 안 라벨 행 「급부 ⊕」를 누르면 급부 박스가 그 목록 끝에, 급부 박스 안 「특성 ⊕」는 특성 박스(§3.4). 박스 머리 왼쪽 ⊖(빼기), 형제가 둘 이상이면 머리 오른쪽 ↑ ↓(순서), 이름 인라인.
  형제가 하나뿐이면 ⊖ 는 잠긴다(「최소 구조 — 세부보장 1개 · 급부 1개는 있어야 한다」). 새 카드는 값 폼이 없다 — 저장한 뒤에야 값 자리가 생긴다. ⊖ 로 뺀 기존 카드는 초안에서 사라진다(되돌리려면 편집 취소).
  읽기 모드에는 구조 조작이 하나도 없다.
- **주석(설명) · 사용처는 화면에 없다** — 주석 값은 데이터에 남고 저장이 그대로 보존한다(지우지 않는다). 탑재 상품담보 수 배지도 없다(2026-10-01) — 영향은 저장 확인, 미리 보려면 관계정보 메뉴.

### 3.7 결정됐지만 미구현

- 상품담보 값 화면은 같은 카드 부품(`Card`)을 구조 조작 없이 쓴다 — 구현 2026-10-27([[기능/상품/상품]] §4.8). 마스터와 다른 칸은 「기본값으로」가 아니라 칸 옆 「현재 마스터 값 가져오기」다.
- **카드 테마** — 현행 모델링 화면(둥근 흰 카드 · 옅은 그림자 · 파란 ⊕ · 빨간 ⊖ · 밑줄 입력 · 토글) — 지금 담보 카드는 앱 공통 토큰(얇은 괘선 · 흰 카드)이다.
- **복제** — 담보 복제(트리 · 마스터 값, 문면 제외, 이름 「<원본> 사본」) · 세부보장 복제(하위 급부까지, 원본 바로 뒤) · 급부 복제 (ADR-0075 결정 4 가 전제로 둠). 서비스 · 화면 모두 없다.
  담보 복제는 노드 키를 그대로 옮긴다 — 문면을 복제해 붙여도 키 경로는 다시 매겨지지 않고 이어진다. 세부보장 · 급부 복제의 사본은 새 노드라 빈 가장 작은 키를 받는다(§3.8).

### 3.8 노드 키 — 담보 안 고정 키 (2026-10-14, [[기능/담보/결정/ADR-0087-담보노드키-키경로참조-함수조항인자연결]] — 구현 2026-10-16)

세부보장 · 급부마다 그 담보 안에서만 뜻이 있는 키를 둔다 — 옛 시스템의 세부보장코드 · 급부번호와 같은 자리다. 담보약관 템플릿은 이 키로 노드를 가리킨다(`@노드` 한정자 · 함수조항 인자 연결 — [[기능/문면/문면]] §3.3 · [[기능/함수조항/함수조항]] §3.7).

- **모양** — 세부보장 `01` · `02` …(두 자리, 99 를 넘으면 자릿수를 늘린다), 급부 `1` · `2` …(그 세부보장 안). 형제 사이에서 유일하다. 경로는 「세부보장 01 › 급부 2」.
- **채번 = 비어 있는 가장 작은 번호** — `01` · `03` 이 있으면 새 세부보장은 `02`. 저장의 최종 트리 기준이다 — 같은 저장에서 ⊖ 로 뺀 노드의 키도 빈 번호라 새 노드가 받을 수 있다. 편집 중 새 카드에도 그 규칙으로 미리 보인다.
- **지운 키는 다시 쓴다** — 실수로 `02` 를 더했다 지우고 다시 더하면 다시 `02` 이고, `02` 를 가리키던 템플릿 참조가 다시 이어진다. 재사용에 영향 확인을 두지 않는다.
  — 왜: 오르기만 하는 키는 잘못 더한 노드를 되돌릴 길이 없다. 다른 뜻의 노드가 키를 이어받는 위험은 감수한다 — 미리보기 · 값 패널([[기능/문면/문면]] §3.9)에 드러나고, 약관을 한 번 읽으면 눈에 띈다.
- **사람이 고치지 않는다** — 입력 칸이 없다. **순서(↑↓)를 바꿔도 키는 그대로**다 — 순서는 수록 순서일 뿐이다.
  — 왜: 순번으로 가리키면 순서를 바꾸는 순간 말없이 다른 노드를 가리킨다. 직접 고치게 하면 중복 · 형식 검사와 「바꾼 키를 가리키던 참조」 규칙이 생긴다.
- **스냅샷도 같은 키** — 키는 이름처럼 뼈대 속성이다(값이 아니다). 탑재 스냅샷 동기화(§3.2)가 키를 옮기고, 상품담보 화면 · 조립은 같은 키로 노드를 찾는다.
- **복제는 키를 그대로 옮긴다** — 담보 복제(§3.7, 미구현)와 문면 문서 복제([[기능/문면/문면]] §3.1)의 키 경로는 다시 매기지 않는다. 새 담보에 그 키가 없으면 끊어진 참조로 드러난다.
- **카드에 보인다** — 카드 머리의 레벨 라벨이 「세부보장 01」 · 「급부 1」이다(§3.6). 급부가 하나뿐인 세부보장도 「급부 1」을 보인다.
- 삭제 영향(§3.2)의 「깨질 참조」는 키 경로로 센다 — 같은 저장에서 지운 키를 새 노드가 다시 받으면 그 참조는 깨지지 않는다.
- **이행** (2026-10-16, 마이그레이션 0027 · 0028) — 기존 담보는 형제 순서대로 키를 채웠고, 저장된 `@<노드id>` 는 그 노드의 키 경로로 바꿨다. 이미 지운 노드를 가리키던 옛 id 는 바꿀 키가 없어 남고 구문 오류로 드러난다 — 다시 고른다.

### `/coverages/new` — 생성

- 경로 `새 담보`, 제출은 헤더 오른쪽.
- 담보명 · 세부보장명 · 급부명 · 설명. **세부보장명은 담보명을, 급부명은 세부보장명을 타이핑에 맞춰 따라간다** — 그 칸을 직접 고치면 그때부터 따라가지 않는다.
- 「세부보장 1 · 급부 1 이 함께 생성됩니다 (최소 구조).」 — 구조를 더 짜는 것은 생성 뒤 상세 화면 `편집` 의 카드에서.
- 담보분류 select(필수 — 열거형 「담보분류」 값, §3.1).
- 생성 → 상세. 거부(담보명 중복 · 빈 이름 · 빈 담보분류 「담보분류를 고르세요」)는 배너.

### `/coverages/<id>` — 상세 (L2 · 한 화면)

탭이 없다. 위에서 아래로 **헤더 · 구조(중첩 카드)** 다. 담보약관 템플릿은 이 화면에 없다(§3.5).

| 자리 | 무엇 |
|---|---|
| **헤더** | 경로 `{담보명}`, 메타 `COV000001`(코드는 읽기 전용 — 편집 대상이 아니다). 탑재 상품담보 수는 두지 않는다(2026-10-01 — 사용처는 관계정보 메뉴). 오른쪽 `편집`(→ `저장`) · 삭제 |
| **구조** | 담보 카드 ⊃ 세부보장 카드 ⊃ 급부 카드 — 카드마다 이름 + 그 레벨의 값 폼 (§3.6). 담보 카드 본문 맨 위에 「담보」(이름) · 「담보분류」 두 줄 — 같은 라벨 열(§3.1 · §3.6) |

- **편집 입구는 하나** — `편집` 을 누르면 모든 카드의 이름 · 값 · 구조 조작 · 담보분류가 한꺼번에 입력기가 된다. 저장 한 번이 담보명 · 담보분류 · 구조 · 모든 카드의 값을 담는다.
- **담보분류 줄** — 값 폼의 행과 같은 모양(라벨 「담보분류」 + ⓘ 「기본 특약 그룹 — 상품에서 다른 그룹에 넣을 수 있다 …」). 읽기는 값 이름, 편집은 select — 열거형 값(순서대로, 「없음」 선택지 없음). 미입력(옛 데이터)이면 「— 고르세요 —」 + 「담보분류를 고르세요」(저장 거부). 열거형에서 지운 값이면 「없는 값 V03」 + 다른 값을 고르라는 줄. 취소하면 모든 카드가 저장값으로 돌아간다.
- 편집 중 ⊖ 로 뺀 것이 있으면 담보 카드 머리 아래 「저장 시 삭제 N개 — 영향을 확인한 뒤 저장된다 (관리자).」
- 담보명에 담보속성 값이 들어가면 담보 카드 머리 아래 경고 한 줄(§3.1).
- 담보속성(갱신유형 · 기본계약 · 추가 …)은 이 화면에 없다.
- 관리자에게는 필드 라벨 옆에 작은 ⓘ 코드 링크 — tooltip 이 `폼키.필드키`, 누르면 `/master/<경로>`. `?node=<level>:<id>&field=<폼키.필드키>` 로 들어오면 필드 행을(필드가 없으면 카드를) 스크롤 · 강조한다 — 마스터 화면 · 오류 메시지의 진입 좌표. `?node=` 없이 `?field=` 만 오면 그 필드를 가진 첫 카드. `?tab=` 은 옛 좌표라 무시한다.

## 5. 미결

- **담보명의 담보속성 값 검사** — 경고로 뒀다. 유효값 목록과 대조해 거부까지 갈지.
- 탑재된 담보의 **순서 변경을 편집자에게** 둔 것 — 조문 수록 순서 변경을 파괴로 본다면 관리자로 올린다 (ADR-0075 열어 둔 것).
- 값 · 참조가 없는 노드의 삭제를 편집자에게 열지 — ADR-0019 경계 개정 사안.
- 저장 시 영향 목록에 문면 조연결 · 보통약관 준용까지 실을지.
- 「신규계약만 적용 = 끔」의 실제 처리(기존 계약 소급의 시점 · 주체) · 면책 나이 일반화(다른 나이가 나오면 토글 → 「n세 이상」 숫자 칸) · 지급률 소수 %(실물에 12.5% 류가 나오면 정수 제한을 푼다).
- 표 출력(최초지급금액표)의 인쇄 폭 초과. 경계 표기는 감액기간 열거값 표시 글자(2026-10-31 구현), 기준일 문구는 동적표 머리글 템플릿 + 인자다([[기능/동적표/동적표]] §3.3).
- 편집 중 **코드 링크(ⓘ)**는 「버립니까?」 확인 없이 화면을 떠난다 — 경로 링크와 같은 확인을 붙일지.
- 시스템 폼에 필드가 더해졌을 때 이미 탑재된 스냅샷에 자리가 생기는가.
- **체증 구현** (§3.4, 2026-11-01 기획) — 폼 · 칩 입력 · 표 구분자 행 펼침. 표 구분자 구현([[기능/구분자/구분자]] §3.7)과 함께.
- `exemption.months` 의 마스터 설명은 「화면은 3M · 1Y 로 받는다」인데 입력은 숫자(개월)다 — 설명을 고치거나 `period` 입력으로 바꾼다.
- 시나리오 [[기능/담보/시나리오/담보트리_시나리오]] S6(모드 분기) · [[기능/담보/시나리오/담보값입력_시나리오]] S1 · S2(노출여부 · 부착)는 옛 규칙이다 — 편집 하나 + 저장 시 영향 확인 · 노드 × 마스터 필드로 다시 쓴다.
- **심사형별 문구의 조건 원천** — 담보약관 조건식이 고지유형(E0005)을 어떤 투영 구분자로 읽을지 — 세부 고지유형(간편심사구분 · 간편심사유형)은 2026-10-29 모델에서 뺐다([[기능/상품/상품]] §3.1). 첫 통합간편 독립특약 적재 때 정한다.

| 구조 추가 = 라벨 행 「세부보장 ⊕」 · 「급부 ⊕」(누르면 그 아래 목록 끝에 박스), 빼기 = 박스 왼쪽 위 ⊖ — 모든 단계에 같은 규칙 · 담보 본문은 라벨 열 하나 (§3.6, 2026-10-21 사용자 결정) | 현행 모델링 화면의 「라벨 ⊕ → 아래 박스 · 박스 왼쪽 위 ⊖」와 같아 학습 비용이 없다. 라벨 열이 하나라 「담보」 · 「담보분류」 입력칸이 한 세로줄에서 시작한다 | 그리드 끝 점선 타일 「+ 세부보장」 · 세부보장 카드 아래 「+ 급부」(2026-09-27 — 추가 자리가 단계마다 달랐다) |
